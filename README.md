# FPGA VGA 顯示控制器 (640x480 @ 60Hz)

## 專案簡介
本專案使用 VHDL 實作 FPGA 的 VGA 螢幕顯示控制器。透過 FPGA 產生符合工業標準的 VGA 同步與色彩訊號，在 `640 × 480 @ 60Hz` 的外接螢幕上畫出**紅、綠、藍三個重疊的矩形色塊**，用來驗證影像輸出時序與 RGB 混色功能。

## 硬體與外部接腳 (Entity)
- **輸入訊號**：
  - `i_clk`：FPGA 板載主時脈（100 MHz）。
  - `i_rst`：重置按鈕（高電位 `'1'` 時將所有計數器歸零）。
- **輸出訊號**：
  - `H` / `V`：水平同步（HSYNC）與垂直同步（VSYNC）訊號，負責通知螢幕換行與換頁。
  - `red` / `green` / `blue`：各 4-bit（共 12-bit 色彩）的 RGB 訊號，`"1111"` 為最亮，`"0000"` 為全暗。

## 內部運作五大模組 (Architecture)
1. **時脈除頻器（100 MHz ➔ 25 MHz）**：
   - `640 × 480 @ 60Hz` 的標準像素時脈約為 `25.175 MHz`。程式透過計數器（`divcnt`）對 100 MHz 主時脈做**除 4 除頻**，產生最接近標準值的 **`25 MHz`** 像素時脈（`divclk`），每跳動一次代表掃描一個像素點。
2. **雙層掃描計數器**：
   - **水平計數器（`h_cnt`）**：從 `0` 數到 `799`（包含 640 個顯示點 + 160 個休息緩衝區）。
   - **垂直計數器（`v_cnt`）**：水平數滿一行後加 1，從 `0` 數到 `524`（包含 480 行顯示區 + 45 行休息緩衝區），數滿代表完成一張完整畫面。
3. **同步脈衝產生器（HSYNC / VSYNC）**：
   - 當計數器走到特定的 Sync 休息區間時，將 `H` 或 `V` 拉低成 `'0'`（負極性脈衝），通知螢幕準備換行或回到左上角重新掃描。
4. **有效顯示區判定（`video_on`）**：
   - 只有在座標落於 `水平 0~639` 且 `垂直 0~479` 範圍內時，`video_on` 才為 `true`（代表目前掃描點位於螢幕可視範圍內）。
5. **畫面渲染與消隱保護（`picture_display`）**：
   - **三原色色塊與混色**：在 `video_on` 為 `true` 時，分別定義紅色（$Y < 360$ 且 $0 < X < 350$）、綠色（$Y < 360$ 且 $250 < X < 640$）與藍色（$120 < Y < 480$ 且 $150 < X < 500$）三個矩形區域。三色重疊處會自動混出**黃色、洋紅、青色**，正中央三色交疊處則呈現**白色**。
   - **消隱保護（Blanking）**：當 `video_on` 為 `false`（掃描點在螢幕邊框外的休息區）時，強制將 RGB 設為 `"0000"`（全黑），避免雜訊干擾螢幕同步。
# FPGA VGA 顯示控制器 

## 一、 核心概念
想像拿一隻畫筆在方格紙上畫畫：**從左上角開始，由左往右畫完一橫排，再跳到下一排繼續畫，全部畫完後再回到左上角重來**。這支程式就是在控制這支「電子畫筆」的移動速度、換行時機，以及每個格子要塗什麼顏色。

1. **為什麼要「除頻」（100 MHz ➔ 25 MHz）？**
   - FPGA 開發板預設心跳速度是 `100 MHz`（每秒跳 1 億次），對 `640 × 480` 螢幕來說太快了。
   - 程式裡做了一個「減速器」（除頻器），讓板子每跳 **4** 次，畫筆才動 **1** 格，速度降成 **`25 MHz`**（每秒畫 2,500 萬個點），剛好符合螢幕每秒更新 60 張畫面的速度。

2. **為什麼水平要數到 `800`、垂直要數到 `525`？**
   - 螢幕真正看得到的畫面確實是寬 `640` 格、高 `480` 格。
   - 畫筆畫完一排（640 格）要拉回最左邊時，需要一段「休息空檔」讓訊號穩定，這佔了 `160` 格（所以水平總共數 `640 + 160 = 800` 格）。
   - 畫完最底下那排（480 排）要回到最左上角時，也需要 `45` 排的空檔（所以垂直總共數 `480 + 45 = 525` 排）。

3. **怎麼讓螢幕知道「要換行」跟「要塗顏色」？**
   - **同步訊號（`H` 和 `V`）**：就像打字機的「換行鍵」。當畫筆走到空檔區時，程式把 `H` 或 `V` 拉低成 `0`，通知螢幕該換行或回到左上角。
   - **有效顯示區（`video_on`）**：用來判斷畫筆現在是不是在「看得到的 `640 × 480` 範圍內」。在範圍內（`true`）就根據座標塗色；在範圍外（`false`）就強制輸出全黑（`"0000"`），避免顏色亂溢出來干擾螢幕。

## 二、 程式碼架構對照
- **Entity (開頭接腳)**：接收板子的 `100MHz` 時脈與重置鈕，輸出 `H/V` 同步線跟 `紅/綠/藍` 顏色線給螢幕。
- **1. 25MHz 時脈分頻器**：讓 `divcnt` 數 0、1 翻轉，把 `100MHz` 降成螢幕需要的 `25MHz` 畫點速度。
- **2. 雙層掃描計數器**：`h_cnt` 負責從左數到右（0~799），數滿一排就讓 `v_cnt` 往下加一排（0~524）。
- **3. HSYNC / VSYNC 同步**：當計數器走到指定的空檔區間時，輸出 `'0'` 脈衝通知螢幕換行或回到左上角。
- **4. 有效顯示區判定**：只要 `X < 640` 且 `Y < 480`，就把 `video_on` 打開（設為 `true`），準備上色。
- **5. 畫面渲染與消隱**：用 `if` 判斷座標範圍，畫出紅、綠、藍三個長方形；不在可視區就強制輸出全黑。
> 我們的**做法分成五個步驟**：
> 1. **首先是時脈除頻**：因為板子原本的時脈是 `100 MHz` 太快了，所以我們寫了一個除 4 的計數器，把它降頻成 **`25 MHz`**，作為畫筆每畫一個像素的速度。
> 2. **第二步是掃描計數**：我們用了水平和垂直兩個計數器，模擬電子束從左到右、從上到下掃描。加上螢幕換行的緩衝空檔，水平總共數 `800` 點，垂直總共數 `525` 行。
> 3. **第三步是同步訊號**：當計數器走到緩衝區間時，程式會把 `H` 和 `V` 同步訊號拉低成 `0`，告訴螢幕該換行或回到左上角重新畫下一張圖。
> 4. **第四步是判定顯示範圍**：我們設定只有在 `640 × 480` 的可視範圍內，才把 `video_on` 打開；如果在範圍外，就強制輸出全黑來做消隱保護，避免雜訊干擾螢幕。
> 5. **最後一步是畫面渲染**：在可視範圍內，我們用 `if` 條件限制 X 和 Y 的座標範圍，分別畫出紅、綠、藍三個長方形。當這三個顏色重疊在一起時，螢幕就會自動混出黃色、青色、洋紅色，正中央三色全疊在一起的地方就會變成白色。以上是我們的報告。」
- **Q1：為什麼紅、綠、藍三個色塊重疊的地方會變色（例如變黃色或白色）？**
  - **回答**：因為這三個 `if` 判斷是**獨立運作**的。當某個座標同時符合紅色和綠色的範圍時，FPGA 會同時送出 `red = "1111"` 和 `green = "1111"`，光的三原色紅加綠就會混成黃色；正中央同時符合三個條件，三原色全開就會變成白色。
- **Q2：如果我想把圖形移動位置或變大變小，要改哪裡？**
  - **回答**：只要改程式碼最下面第 5 部分（`picture_display`）裡面的 `horizontal`（X 座標）和 `vertical`（Y 座標）的數字範圍就可以了。
